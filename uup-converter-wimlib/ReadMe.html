概述

  • 这是一个自动化的 Windows 命令行脚本，用于处理微软 Windows 11/10 的统一更新平台（UUP）文件，将其构建或转换成可用状态（ISO / WIM）。

  • 你可以通过执行从 Windows 11/10 当前版本升级到更高版本（从 15063，即 1703 版本开始）的操作来获取 UUP 文件。

  • 你也可以使用以下项目获取 UUP 规范源码：
    Open UUP dump 项目
    UUP 生成项目

使用说明

  • 运行此脚本需要管理员权限。

  • 可选步骤：临时禁用杀毒软件或防护程序，以免干扰处理过程。

  • 确保文件不是只读状态，且未被锁定。

  • 将本工具包解压到一个路径简单且不含空格的文件夹中（例如：C:\UUP），以避免出错。

  • 将 UUP 文件放置在 "UUPs" 文件夹中以便自动检测，或者将包含 UUP 文件的目录拖放到 convert-UUP.cmd 上。此外，系统也会提示你输入其他的 UUP 文件夹路径。

  • 如果检测到多个版本，系统会提示你选择特定版本、部分版本或创建合集（AIO）。

  • 若要退出提示或选项菜单，只需按下“Enter”键。

输出选择

  • 1 - 创建带有 install.wim 的 ISO
    4 - 创建带有 install.esd 的 ISO

    将 UUP 文件转换为包含 install.wim 或 install.esd 文件的常规 ISO 发行版。

  • 2 - 仅创建 install.wim
    5 - 仅创建 install.esd

    仅创建 install.wim/install.esd 文件，可用于相同版本的其他 ISO，或用于通过 dism、imagex、wimlib 进行手动部署。

  • 3 - UUP 版本信息

    显示检测到的版本信息（架构、语言、内部版本号、分支、版本名称）。

  • 6 - 配置选项

    更改配置选项的状态。

配置选项

控制转换行为、输出和自动化。

你有三种方法可以更改这些选项的状态，其中 0 表示关闭（否），1 表示开启（是）：
- 编辑 ConvertConfig.ini 中 [convert-UUP] 和 [Store_Apps] 相关的部分
- 删除 ConvertConfig.ini 并直接编辑 convert-UUP.cmd 脚本
- 使用菜单选项 6（此方法不包含所有选项）

  • AutoStart (自动启动)

    直接开始转换过程，无需提示。

    这需要将 UUP 文件放在 UUPs 文件夹中，或者从命令行启动 convert-UUP.cmd 并附带 UUP 源码文件夹路径，或者将 UUP 源码文件夹拖放到 convert-UUP.cmd 上。

    设置此选项为 1 以创建带 install.wim 的 ISO
    设置此选项为 2 以创建带 install.esd 的 ISO
    设置此选项为 3 以仅创建 install.wim
    设置此选项为 4 以仅创建 install.esd

  • AddUpdates (添加更新)

    转换后，将检测到的更新集成到 ISO 发行版或 install.wim 中。

    设置此选项为 1 以集成更新到 wim 文件中
    设置此选项为 2 以将更新外部添加到 ISO 发行版中

    详见 添加更新选项。

  • StartVirtual (启动虚拟版本创建)

    转换完成后直接启动 create_virtual_editions.cmd。

    详见 虚拟版本。

  • wim2esd

    最后将 install.wim 转换为 install.esd。

    此选项旨在与 AddUpdates 选项配合使用。

    如果你选择了 install.esd 且开启了 AddUpdates，此选项将自动启用。

    警告：创建 install.esd 将消耗大量 CPU/内存，且需要相当长的时间。

  • wim2swm

    将 install.wim 分割成多个 install.swm 文件。

    如果 install.wim 大小低于 4 GB，此选项将自动禁用。

    如果 wim2esd 和 wim2swm 同时开启，install.esd 的优先级高于分割的 install.swm。

  • SkipISO (跳过 ISO)

    如果你目前不打算创建 ISO 文件，或者想稍后用 multi_arch_iso.cmd 创建多架构 ISO (x86/x64)，或者打算手动使用 create_virtual_editions.cmd。

  • SkipWinRE (跳过 WinRE)

    不将 winre.wim 添加到 install.wim/install.esd 中。如果你不需要恢复环境，或者想减小 ISO 体积/缩短转换时间等，可以使用此项。

    注意：向 install.esd 添加 winre.wim 会消耗大量 CPU/内存。

  • LCUwinre

    即使检测到 SafeOS 更新，也强制使用累积更新（LCU）更新 winre.wim。

    对于 26052 及更高版本，此选项将被忽略并自动禁用。

  • LCUmsuExpand

    展开累积更新并从散件文件（通过 update.mum）安装，而不是直接添加 msu 文件。

    此选项仅适用于 Windows 11 Build 22621 及更高版本。

    对于 Windows 11 Build 26052 及更高版本，选项状态：
    - 选项自动启用。
    - 将选项设置为 2 或 3 可禁用，并仅添加最新 LCU msu。
    - 对于包含基线 KB5122055 的 Insider 版本，选项自动设置为 3。
    - 如果 LCU msu 包含 MumX v2，选项自动设置为 3。

  • DisableUpdatingUpgrade (禁用更新优化)

    禁用通过版本升级（如 家庭版>专业版 / 标准版>数据中心版）进行的更新过程优化，并为每个版本执行单独更新。

    对于 Windows 11 Build 26000 及更高版本，此选项自动启用。设置为 2 以恢复为关闭状态。

  • UpdtBootFiles (更新启动文件)

    使用累积更新中的新文件更新 ISO 启动文件（bootmgr/memtest/efisys.bin）。

    此选项还将更新检测到的新 UEFI CA 2023 启动文件。详见 KB5053484。

    注意：即使此选项关闭，bootmgr.efi/bootmgfw.efi 这两个默认文件也会被更新。

  • ForceDism (强制使用 Dism)

    使用官方的 dism.exe 方法创建 boot.wim，这需要 Windows 11/10 宿主系统或 ADK。

  • RefESD (保留参考 ESD)

    保留转换后的参考 ESD 文件供将来操作使用，而不是每次都重新转换。

    如果 UUP 源码是 Express 类型，参考 ESD 和版本 ESD 将被复制到新文件夹 "CanonicalUUP"。实际上，这将 Express UUP 源码转换并备份为规范格式。
    如果 UUP 源码是规范格式，参考 ESD 将被复制到同一个 UUP 源码文件夹，原始 CAB 文件将被移动到子目录 "Original"。

  • SkipLCUmsu

    对于 Build 21382 到 25330，跳过创建累积更新 MSU（LCU 将使用旧的 cab+psf 解压方式添加）。

  • SkipEdge (跳过 Edge)

    跳过添加 Microsoft Edge Chromium。
    设置选项为 1：对于 Windows 11 Build 26052 及更高版本，不添加 Edge.wim。
    设置选项为 1：对于 Windows 10，不将 Edge 集成到累积更新中。
    设置选项为 2：通过另一种变通方法跳过 Windows 10 累积更新中的 Edge（可能无效）。

    此选项仅在 AddUpdates=1（集成）时生效。

  • AutoExit (自动退出)

    转换完成（脚本运行结束）后自动退出，无需提示。

    适用于多批次转换，建议与 AutoStart 配合使用。

  • AddDrivers (添加驱动)

    向 install.wim 和 boot.wim / winre.wim 添加驱动程序。
    这是基础功能支持，应仅用于已测试且兼容的驱动。

    * 如何使用：
    - 启用该选项。
    - 将要添加的驱动程序放入相应的子文件夹中：
    ALL: 驱动将被添加到所有 wim 文件中
    OS: 驱动仅被添加到 install.wim
    WinPE: 驱动仅被添加到 boot.wim / winre.wim

    * 可选：你可以使用 Drv_Source 选项指定不同的驱动源码文件夹路径。
    该文件夹必须包含上述驱动目标的子文件夹。

    * 此选项仅在集成更新或应用时生效。

    * 此选项不会检查或验证驱动程序，它只是简单地将 DISM 指向驱动程序文件夹。

    * 此选项适用于简单且关键的启动驱动（芯片组、磁盘控制器、局域网/无线网卡等）以方便安装，不适用于大型驱动或可能破坏安装程序的驱动。

  • SkipApps (跳过应用)

    不添加应用商店（Store）应用。

添加更新选项

信息

  • 从 Windows 10 1709 版本开始，服务堆栈更新（SSU）和最新的累积更新（LCU）通过 UUP 源码进行处理和分发。此外还包含一些用于升级的小型动态更新。

  • 因此，Open UUP dump 项目 会针对同一个 Windows 11/10 版本提供多个内部版本。每个版本代表刷新的功能更新或新的累积更新。

  • 但是，这些更新仅由 Windows Update 使用和应用，它们本身并不是 UUP 源码的实际部分，默认情况下不会包含在转换后的 ISO/WIM 中。

  • AddUpdates 选项提供了内置能力来直接集成这些更新，从而生成一个刷新的 ISO/WIM，或将其外部添加。

  • 集成 (Integrate) 更新模式仅适用于 install.wim（ISO 或单个 wim），且需要 Windows 11/10 宿主系统或 Windows 11/10 ADK。

  • 外部 (External) 更新模式仅适用于 Build 17763 及更高版本，更新将在安装过程中（全新安装或升级）安装。

  • Cleanup (清理) 选项控制集成模式下的映像清理，并会对被取代的组件进行增量压缩。

  • ResetBase (重置基准) 选项仅在开启清理选项时生效，并将进一步移除被取代的组件。

  • NetFx3 选项用于为两种模式启用 .NET 3.5 功能。
    注意：对于 Windows 11 Build 27965 及更高版本，.NET 3.5 不再作为一项功能包含在内。

  • 外部更新模式是作为备份方案提供的，以防未安装 Windows 11/10 ADK，或者用户希望更快完成 ISO 转换。如果条件允许，建议使用正常的集成模式。

  • 如果 UUP 源码为 Build 17063 或更高版本且选择了多个版本，为了缩短集成模式的时间，如果可能，专业版/专业 N 版将作为已更新的家庭版/家庭 N 版的升级版来创建。

  • 类似地，对于 Windows Server 2022，如果可能，数据中心版将作为已更新的标准版的升级版来创建。

  • 集成更新模式在 Windows 7 宿主系统上可能无法正常工作，尤其是对于最近的 Windows 11/10 版本。在这种情况下，建议使用外部更新模式。

  • 针对 ARM64 UUP 映像的集成更新模式仅在 Windows 11/10/8.1 宿主系统上有效。

  • 针对 Windows 11 Build 22567 及更高版本的集成更新模式要求至少为 Windows 10 v1607 宿主系统 (Build 14399)。

操作方法

  • 确保 UUP 源码包含更新文件（Windows10.0-KB* / Windows11.0-KB* 文件）。

  • 将配置选项 AddUpdates 设置为 1 或 2。

  • 如果你设置为 1 但未安装 Windows 11/10 ADK，它将被还原为 2（如果该版本支持），或直接关闭。

注意

    警告：在 Build 18362 及更高版本上，由于微软累积更新设计的变更，Cleanup 选项还会移除基础的 RTM 版本包。
    这可能会导致未来的累积更新安装失败。

    尽管如此，系统本身可以在安装后启动清理进程，通过计划任务 StartComponentCleanup 或 SilentCleanup，或通过磁盘清理来进行。

    警告： ResetBase 选项会破坏“重置此电脑”功能。对于 Build 18362 及更高版本，全量 ResetBase 已自动禁用。

虚拟版本

信息

  • 从 Windows 10 Build 17063 开始，常规版本已统一为两个基础版本：家庭版和专业版（及其变体家庭 N 版和专业 N 版）。

    家庭中文版仍然是独立的。

  • 因此，UUP 将仅交付上述版本的安装文件。

  • 以下版本现在作为基础版本的“虚拟升级版本”存在：

    家庭版 -> 家庭单语言版
    专业版 -> 企业版、教育版、专业教育版、专业工作站版、Cloud (Build 21364+)、企业多会话版、IoT 企业版 (Build 18277+)、IoT 企业订阅版 (Build 25982+)
    专业 N 版 -> 企业 N 版、教育 N 版、专业教育 N 版、专业 N 工作站版、Cloud N (Build 21364+)
    企业 LTSC -> IoT 企业 LTSC (Build 19041+)、IoT 企业 LTSC 订阅版 (Build 25193+)

  • 因此，这个额外的脚本是为了帮助从 UUP 源码创建这些附加版本。

操作方法

  • 支持的源码发行版：
    - 放在脚本旁边的文件夹（包含解压后的 ISO 内容）。（自动检测）
    - DVD 驱动器，即挂载的 iso/真实的 dvd 驱动器/usb 驱动器。（自动检测）
    - 直接的 ISO 文件。（系统会提示你指定一个）

  • 可选：如果你不打算保留基础的转换 ISO，将 convert-UUP 选项 SkipISO 设置为 1。

  • 使用 convert-UUP.cmd 创建源码发行版。

  • 运行 create_virtual_editions.cmd 并从菜单中选择所需选项。

选项

  • 1 - 创建所有版本
    创建所有可能的虚拟目标版本。

  • 2 - 创建一个版本
    创建一个特定的虚拟目标版本。

  • 3 - 创建随机选择的版本
    创建部分虚拟目标版本。

配置选项

控制过程行为、输出和自动化。

你有两种方法可以更改这些选项的状态，其中 0 表示关闭（否），1 表示开启（是）：
- 编辑 ConvertConfig.ini 中 [create_virtual_editions] 部分
- 删除 ConvertConfig.ini 并直接编辑 create_virtual_editions.cmd 脚本

  • UseDism

    选择创建方法：

    值 0：注册表操作
    “黑科技”方法，适用于 install.wim 或 install.esd，支持任何宿主系统 (Vista+)。

    值 1：Dism.exe 工具
    官方方法，仅适用于 install.wim，需要 NT 10.0 宿主系统或带有 Windows ADK 的 Windows 8.1。

    值 2：强制使用 Dism.exe 工具
    同值 1，但支持带有 Windows ADK 的 Windows 7/8。

    如果选定值为 1 或 2 且宿主系统为 NT 6.x 且未安装 Windows ADK，它将自动还原为值 0。
    如果选定值为 1 或 2 且源码文件是 install.esd，它将自动还原为值 0。

  • AutoStart

    直接开始创建过程，无需提示。
    这需要源码发行版（文件夹或驱动器）已就绪。
    仅会创建 AutoEditions 中指定的版本，如果未指定版本（为空），则创建所有可能的版本。

  • AutoEditions

    指定在使用 AutoStart 选项时自动创建的版本，用逗号分隔。
    留空则创建所有可能的版本。

    支持的版本值：
    Enterprise, Education, ProfessionalEducation, ProfessionalWorkstation, CloudEdition, ServerRdsh, IoTEnterprise, IoTEnterpriseK
    EnterpriseN, EducationN, ProfessionalEducationN, ProfessionalWorkstationN, CloudEditionN
    CoreSingleLanguage
    IoTEnterpriseS, IoTEnterpriseSK

    示例：
    vAutoEditions=Enterprise
    vAutoEditions=Enterprise,ProfessionalWorkstation,Education
    vAutoEditions=

  • SortEditions (版本排序)

    指定要按顺序排序的所有或任何版本，用逗号分隔。
    一旦填写，该选项将启用。留空则保持禁用。

    注意：
    这应包括你想要的源版本或任何已存在于 install.wim/install.esd 中的版本。
    通常，你可以指定任何正确的版本 ID，如果在源文件中检测到，它将被包含（并排序）。

    警告：
    任何未在此选项中指定的版本，将不会被包含在最终的 install.wim/install.esd 中。
    请务必指定所有需要的版本。

    示例：
    - 启用：
    vSortEditions=CoreSingleLanguage,CoreCountrySpecific,Core,CoreN,Professional,ProfessionalN
    vSortEditions=Professional,ProfessionalWorkstation,Enterprise,ProfessionalN,ProfessionalWorkstationN,EnterpriseN
    vSortEditions=Enterprise EnterpriseN EnterpriseS EnterpriseSN IoTEnterpriseS IoTEnterpriseSK

    - 保持禁用：
    vSortEditions=

  • DeleteSource (删除源版本)

    不保留源版本（例如：创建企业版并删除专业版）。

  • Preserve (保留)

    保持源发行版文件夹完整，操作将在其副本上进行。
    如果源发行版是 ISO 文件，此选项无效。

  • wim2esd

    最后将 install.wim 转换为 install.esd。

    警告：创建 install.esd 会消耗大量 CPU/内存，且可能需要相当长的时间。

  • SkipISO

    最后不创建 ISO 文件。

注意：

如果 create_virtual_editions.cmd 是从 convert-UUP.cmd 启动的，选项 AutoStart、wim2esd 和 SkipISO 将继承自 convert-UUP 部分，无论它们在虚拟版本部分的当前状态如何。

也就是说，如果 convert-UUP 的 AutoStart=1，脚本将自动创建虚拟版本；
如果 convert-UUP 的 wim2esd=1，install.wim 将被转换为 install.esd，否则跳过转换。

多架构 ISO (x86/x64)

操作方法

  • 可选：如果你不打算保留单架构 ISO，编辑 convert-UUP.cmd 并 设置 SkipISO=1。

  • 使用 convert-UUP.cmd 创建两个 ISO 发行版，一个用于 x64，另一个用于 x86，你可以选择每个发行版中包含的版本。

  • 运行 multi_arch_iso.cmd 并从菜单中选择所需选项。

选项

  • 1 - 创建包含 1 个合并 install.wim/install.esd 的 ISO
    创建一个自定义 ISO 结构。
    所有 x64/x86 映像共用 1 个 install.wim/install.esd，并稍微修改 bootx64.wim/bootx86.wim 以允许共存。

  • 2 - 创建包含 2 个独立 install.wim/install.esd 的 ISO (Win 10)
    创建与媒体创建工具（Media Creation Tool）相同的 ISO 结构。
    拥有两个独立的 x64/x86 文件夹，每个架构有各自的 install.wim/install.esd。

注意

  • 要保留源单架构发行版文件夹，编辑 multi_arch_iso.cmd 并 设置 Preserve=1。

  • 如果安装文件是 install.esd，请注意选项 1 在统一 install.esd 文件时需要消耗大量 CPU/内存。

  • multi_arch_iso.cmd 也可用于从任何类似的 Windows x64/x86 ISO 发行版创建多架构 ISO，从 Windows 7 SP1 开始支持。
    然而，选项 2 仅适用于 Windows 11/10 安装文件。

调试模式

旨在帮助检测脚本或转换过程中的错误，并创建完整的操作日志。

要启用调试模式，请按以下步骤操作：

  • 在 ConvertConfig.ini 中设置所需的配置选项（尤其是 AutoStart）。

  • 编辑 convert-UUP.cmd 并将 set _Debug=0 更改为 set _Debug=1 并保存更改。

  • 开始处理：将 UUP 文件放入 UUPs 文件夹，然后以管理员身份运行脚本。

  • 另一种开始方法：将 UUP 文件源目录拖放到 convert-UUP.cmd 上。

  • 等待处理结束且命令行窗口关闭。

注意：如果 StartVirtual 选项处于活动状态，create_virtual_editions.cmd 将继承调试模式。

补充说明

  • 如果转换或更新过程失败且出现“拒绝访问”错误，请以管理员身份运行 Remove_Failure_MountDir_TempDir.cmd，以移除临时挂载目录和提取残余。

  • 如果升级是通过 Express UUP（下载目录中有多个展开的文件夹）进行的，你需要在开始升级过程之前（第一次重启之前）执行 UUP > ISO 操作。
    为此，当 Windows Update 提示你重启时，启动 convert-UUP.cmd 并粘贴下载目录的路径，例如：
    • C:\Windows\SoftwareDistribution\Download\07172dda91861218ecc095600216d792

    或者，如果你是在虚拟机中测试或拥有多启动系统，你可以选择关闭/重启系统而不进行升级。
    在桌面上按下 Alt+F4 并选择不带“更新”字样的选项。
